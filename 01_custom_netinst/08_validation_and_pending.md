## Installation profile acceptance matrix

| Choice | Install-time action | Validation |
|---|---|---|
| Base Debian | Interactive install, minimal, SSH + standard utilities, manual disk selection | Boots UEFI, ext4 OS filesystem, hostname, local/root passwords, DHCP, confirmed installation target |
| Backports | Explicitly enable `trixie-backports` at default priority **100**; review/complete eligible upgrades, autoremove and purge leftovers | Full upgrade and cleanup confirmed; all proposed removals explicitly reviewed; no eligible upgrades left; no critical package removed |
| Ensure 7.x kernel branch | With Backports selected, prefer compatible Backports Linux **7.x** image/headers; otherwise use standard repos, requesting Backports only if needed | Correct 7.x kernel, matching headers, GRUB and original stable fallback; explicit repo selection, no fixed version lock or global pin |
| Extended device support | Attempt **both** `intel-microcode` and `amd64-microcode`, plus broad firmware; when Backports is selected, prefer its viable versions package-by-package | Joint mixed-source APT simulation; **each Stable fallback's name/version/source/reason shown in one final transaction approval**; genuine omissions individually approved/logged; compatible packages installed |
| ZSTD ZRAM | Generator, newly created or reused target-assigned swap with native manual fallback, compressed writeback, monitor and ZRAM-only `vm.swappiness=100` | Kernel support/ordering verified; effective swappiness 100 only when selected; appropriate emergency behavior, monitor restart and no independent swap |
| Debian tweaks | Non-default OS settings only; no ZRAM, firmware, repository pinning or kernel installation | Root mount exceptions, manual-only filesystem repairs, root SSH disabled, no unattended updates  |
| OpenMediaVault 8 | OMV package installation only plus disable OMV cron-apt; user configures OMV afterwards | Package transaction safe; networking and the installer-confirmed administrator account SSH/sudo work; root SSH disabled; OMV cron-apt is inactive |
| Docker | Official Docker engine, containerd, Buildx and Compose CLI | Packages installed, `docker.service` and `docker.socket` inactive/disabled until approval |

**All seven optional profiles are separately displayed and initially unchecked, in this exact menu order: Backports → Ensure 7.x kernel branch → Extended device support → ZRAM → Debian tweaks → OMV → Docker.** **Approved final selection confirmation (Option A):** native Debconf summary of all seven Selected/Not selected states and dependencies, followed by a negative-default confirmation **before** any selected-profile operations, using GTK in Graphical install and equivalent prompts in text mode. This requires a tested early Simple-CDD integration; if not achievable before execution, use individual confirmations (conditional Option B), never a misleading late prompt. Debian tweaks is **independent of Ensure 7.x**; it neither requires nor installs a 7.x kernel, and must work with the default Debian kernel. ZRAM can be selected without Debian tweaks, but it **requires explicit selection of Ensure 7.x**. If Ensure 7.x is unchecked, offer to select it or deselect ZRAM. When Backports was explicitly selected, Ensure 7.x evaluates compatible Backports 7.x image/headers first, with a normal-repository fallback; otherwise it checks normal Debian repositories first and offers explicit Backports selection only if necessary. Backports remains at priority **100**, owns the reviewed eligible-package upgrade and cleanup; Ensure 7.x owns selective installation of kernel-related backported packages. No optional profile is selected automatically.

## Blocking verification issues

**Do not ask new planning questions for built-in Debian Installer behavior** (network and mirror selection, locale, time, keyboard, account screens, native disk confirmation, tasksel, standard retries or their ordinary persistence). Implement and test the native prompts. Only escalate genuinely custom, consequential choices that cannot be determined by existing confirmed policy.

1. **Selective Backports compatibility versus OMV 8:** Debian's default Backports priority **100** replaces the revoked priority **900**. Check metapackage candidates and any explicitly selected backported dependencies; simulate selected OMV and Docker transactions. Do not create a global higher-priority pin.
2. **Dependency chain and Backports-first kernel selection:** ZRAM **requires explicitly selected Ensure 7.x**, never auto-selects it. **If Backports is selected**, Ensure 7.x first evaluates compatible moving **Backports** 7.x image/header packages; if not usable, reviews normal-repository 7.x fallback. **Without Backports**, check normal repositories first and ask for explicit Backports selection only when necessary. The Backports profile keeps **priority 100** and performs its reviewed eligible-package full upgrade and separately approved cleanup **before** downstream profiles. Ensure 7.x selectively requests the needed kernel Backports versions where suitable. Stop on incomplete upgrades, unapproved removals or conflicts, retaining the stable fallback kernel.
3. **ZRAM API compatibility:** verify selected kernel and Debian generator support resident limit, compressed writeback, early device setup and dynamic backing-size measurement; inspect uploaded monitor for logic/errors.
4. **User-controlled swap partition, conversion immediately at ZRAM profile entry:** user creates a GPT swap partition or reuses existing GPT swap in ordinary Debian Installer partitioning (16 GB suggested). Without ZRAM, it remains conventional swap. **As the first ZRAM profile action**, prefer the uniquely identified swap assigned in the installed target's `/etc/fstab`; if ambiguous, require an explicitly chosen candidate from the native GTK/text Debconf list (safe default: stop); **immediately upon explicit confirmation** of the exact partition and destructive action, convert that *same selected partition* to **generic Linux filesystem GPT type 8300** (GUID `0FC63DAF-8483-4772-8E79-3D69D8477DE4`) and assign the GPT **PARTLABEL `zram-writeback`**, not a filesystem LABEL. Leave it **raw and unformatted**, remove prior swap signatures safely, and make it exclusively ZRAM backing via the **verified PARTUUID**. Never mount or independently activate it as swap. **If Debian Installer already activated that exact swap partition, inspect memory/swap usage and obtain separate explicit permission for a targeted `swapoff`; require success and verify it is inactive before the GPT/signature change.** Do not attempt when insufficient RAM is likely; on failure stop and keep the partition's type/signatures unchanged. No `swapoff -a`, forced deactivation or silent retries. If absent and ZRAM selected, stop without modification; validate whether a real return-to-partitioning/deselect option can be implemented at the late-command stage before claiming that it works. Validate partman timing, swap activation, `/etc/fstab`, GPT writes, user confirmation and safe navigation before shipping.
5. **Emergency recovery:** ensure systemd *really enters* emergency mode for a failed ZRAM initialization, with usable local root credentials; test this in a disposable environment.
6. **OMV / SSH / network:** ensure OMV does not enable root SSH or block the installer-confirmed administrator account; check DHCP and DNS.
7. **OMV scheduled updates:** verify environment variable and Salt deploy method on exact OMV version; confirm cron-apt is disabled. Verify Debian APT unattended package installation separately.
8. **Installer GUI defaults and interaction:** [profile_defaults.conf](my-cdd/profile_defaults.conf) is now rendered by `build.sh` into boot and preseed defaults, and remains the single canonical source for editable suggestions (hostname, username, empty domain, English/`en_US.UTF-8`, Spanish keyboard, `Europe/Berlin`, UTC RTC, DHCP and headless SSH/standard tasks). Validate mapping of symbolic keys to actual installer questions, on-screen editability, confirmation, account/sudo/root-password ordering and use even when Debian tweaks is unchecked. Do not put secrets, fixed disk targets or profile preselection in this file.
9. **Docker service suppression:** ensure packages install without starting daemon/socket, including during package maintainer scripts.
10. **Extended device support:** attempt to install **both** `intel-microcode` and `amd64-microcode` regardless of actual CPU vendor, plus the full broad firmware inventory. **If Backports was explicitly selected, prefer available compatible Backports versions for each requested firmware/microcode package before Stable; otherwise use normal repositories.** Make selective per-package Backports requests while keeping global priority **100**, avoid blanket `-t` and re-simulate the mixed-source transaction. **List every Stable fallback with package name, exact version, source and reason; one explicit final APT transaction approval is sufficient for all those disclosed fallbacks (no individual fallback prompts).** Debian's normal vendor-specific microcode recommendation is superseded here by the user's explicit request. Separately review dependencies/removals. **For each unavailable/conflicting firmware or microcode package**, display its name, actual failure reason, and potential impact (including CPU security/stability implications), require **individual explicit approval to omit**, re-simulate the remaining set, install all remaining compatible packages and record each approved omission in diagnostic logs. No silent skips or unsafe removals. A failed actual install cannot be marked omitted until APT/dpkg consistency is restored through reviewed operations.
11. **OS installation target selection:** require explicit confirmation of the installation disk and destructive partition writes; validate the selection procedure using disposable test disks.
12. **Installer media verification — resolved: none.** Do not require Debian source-image checksum/signature verification, generated ISO hashes, USB read-back or media verification-only boot tests. Keep the requested UEFI/BIOS and installer functionality as design requirements; signed APT repository metadata and package compatibility checks are separate.
13. **Manual failure recovery and diagnostics:** induce critical optional-profile failures in disposable tests; verify installation stops, **always displays diagnostics and offers manual export**, attempts to save a custom log bundle under **`/target/var/log/installer/`** if the target is safely mounted/writable, and independently attempts a **second copy to a positively identified writable area of the installer USB**. If either destination is unsafe/unavailable, report the limitation without destructive workarounds. No snapshot/backup/rollback/reinstall action is automatic. Determine which logs survive failed installations and hard reboots.

14. **Final profile-summary integration (method A approved):** Debian Installer's GTK cdebconf supports custom note/boolean prompts; Simple-CDD **0.6.9** uses a Debconf multiselect and immediately queues package activity afterward. The user selected **an early `preseed/early_command` hook with the upstream udeb unchanged**, rather than a custom udeb or removing the additional summary. Source now invokes the gate before `anna-install simple-cdd-profiles`, loads the generated profile template, displays seven statuses/dependencies and requires default-No approval. **No runtime validation yet**: confirm Debconf template availability, `seen`-flag behavior without double prompting, navigation/cancellation, zero/one/many selections, and no effects before approval in GTK and text. A `profiles/*.postinst` or late_command-only prompt is too late. **If the hook does not work, stop and ask rather than switch methods or silently remove confirmation.**

**Decision recorded (2026-11-14):** authorized **A — existing early preseed hook**. No upstream udeb patching. [`my-cdd/profiles/default.preseed`](my-cdd/profiles/default.preseed) now runs the confirmation script before `anna-install` with shell `&&` to block the subsequent command on refusal. This is **not yet demonstrated in a running installer**. The earlier alternative of deleting the extra confirmation requires separate explicit permission if method A proves infeasible.

15. **Native network/mirror workflow, no duplicate custom prompts:** validate that Debian Installer's ordinary network, mirror, package-download/retry and installed-APT configuration interactions remain native and work in GTK/text modes. **Do not introduce a separate custom Retry/Change mirror/Stop dialog for ordinary installer steps**, and **do not ask a separate mirror-persistence question**. During later selected custom-profile operations, test whether the native recovery UI can safely be reused; if not, stop with diagnostics and manual intervention. Preserve signed metadata, repository identities, previously approved profile selections and package transaction approval rules. This is a technical integration test, not another planning decision.

## Failure policy and evidence

- **Critical selected-profile failure:** after any approved explicit network retry or mirror-change opportunity fails or the user chooses Stop, **stop, always display diagnostics and offer manual export**. Attempt a controlled log copy at **`/target/var/log/installer/`** only if the correct target filesystem is mounted/writable, and independently copy the diagnostics to the **installer USB when a safe writable area is available**. Report each save path or failure separately; do not modify media or repartition for logging. Recovery or reinstallation remains **manual**. No installer-generated snapshot, system-image backup, restore point, automatic rollback or fallback to a different profile; never falsely report success.
- **ZRAM init failure:** enter systemd emergency mode for local recovery, requiring a root password set during installation.
- **ZRAM monitor failure:** log and restart the monitor; do not independently trigger emergency mode.
- **Update installation:** user approval only (security included); no automatic reboots. Permitted package removals require explicit review and approval; after an approved full upgrade, separately review and approve `apt autoremove --purge` and any residual-configuration purges. Preserve the initially available stable fallback kernel.
- **Resolved — full diagnostic copies, no sanitization:** retain **the complete available unredacted** Debian Installer and custom-profile messages, `apt-cache policy`, simulated transactions, profile selections, confirmed partition identifiers and exit status in **both** installed-target and installer-USB copies when the respective destinations are safely writable. **Do not redact, filter or selectively omit existing log content in either copy.** Do not intentionally add credentials to logs or scripts; unredacted existing logs may nonetheless contain secrets. Use **root-owned restrictive access (directory 0700, files 0600, where supported)**; a removable filesystem may not support POSIX permissions, so explicitly warn instead of falsely claiming protection. **Always display diagnostics and a sensitive-log warning, and offer manual export of the unredacted logs.** This choice resolves the earlier credential-redaction question; it does not authorize snapshots, backups or rollback.
- **Persistence and privacy tests:** check missing/unmounted/read-only target, read-only/absent/full installer USB, and both destinations failing. Verify complete matching diagnostic content in both copies whenever both writes succeed, permission restrictions **where supported**, USB confidentiality warnings where permissions cannot be enforced, and an **always-visible sensitive-content warning with manual export**. Do not claim a USB copy was saved until confirmed; reuse Debian Installer's existing **Save debug logs** path where applicable.

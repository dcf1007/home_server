# Native Debian Installer integration (source only)

**ZRAM native partition tool correction (2026-11-15):** The latest disposable graphical VM passed root recovery, Backports, and the selected Linux 7.x kernel and headers. The ZRAM profile then stopped in its prerequisite check: `parted` was unavailable in Debian Installer. The project now includes Debian's official Trixie `parted-udeb` through the existing Simple-CDD build-only `installer-media.udebs` file; the selected ZRAM profile loads it through native `anna-install` only if needed and verifies `parted` before disk operations. The ISO builder confirms the archive and installer index are present. No normal `parted` .deb is installed into the target, no binary is copied across environments and all destructive approvals remain unchanged. Target-side util-linux tools from the preceding correction still run through the supported `in-target` chroot with target libraries. **Source-only; no new ISO or partition-conversion runtime test.**


**Current ZRAM installer-utility correction (2026-11-15):** The latest graphical VM completed Backports, Linux 7.x and the selected broad firmware transaction (both restricted firmware licenses accepted), then stopped at the *start* of ZRAM with `ZRAM conversion requires unavailable installer utility: lsblk`. Debian Installer is a minimal udeb environment and does not provide the normal target's full `util-linux` command set. The selected ZRAM profile now checks the installer's required `parted`, `readlink` and `cmp`, and verifies `lsblk`, `blkid`, `findmnt`, `swapon`, `swapoff` and `wipefs` in the **already installed target**. Those tools run only via Debian Installer's native `in-target --pass-stdout` helper, preserving their normal libraries and device/proc/sys mounts. The installed root's `/target` mount check stays in the installer namespace using `/proc/self/mountinfo`. No new package or udeb is installed, no host binaries are copied into the installer, and all existing PARTUUID/GPT/mount/holder/memory/targeted-swapoff and separate default-No destructive approvals remain. The screenshots show no ZRAM conversion had yet occurred. **No new ISO build, partition write, graphical ZRAM run or first-boot validation has been performed.**


**Native package progress and firmware-license handling (2026-11-15, source only):** The latest graphical VM reached Backports, a selected Linux 7.2 kernel and the full 40-package firmware transaction. The firmware install failed at `firmware-ipw2x00` and `firmware-ivtv`, whose package-native Debconf licenses require explicit consent; its syslog reported an unavailable target Debconf Passthrough fd 3. The selected-profile runner now uses Debian's `debconf-apt-progress` with `apt-get` for live APT operations, using the **same `apt-get` frontend** for transaction simulations and security reviews. The firmware profile downloads the **exact selected binary package version** without installing it, extracts its full native Debconf license template, displays a separate default-No license decision through the existing GTK/text Debian Installer interface, and stores the accepted answer only after explicit agreement in target Debconf before unpacking. A refusal triggers the existing per-package omission approval; if approved, the full revised APT transaction is re-simulated and reviewed again, and an omitted license package must not reappear as a dependency. A declined omission aborts. All original firmware names and Backports priority 100 are retained. **No patched udeb, shortened license, blanket acceptance, silent omission or completed installer runtime validation.**

**2026-11-15 follow-up VM failure (root recovery succeeded):** With all seven profiles selected, the native password prompt established a usable root password and the service-start policy preflight succeeded. The Backports profile then failed at `apt update` because an active `cdrom:` source from the installer was still present; network repositories were reachable. The profile loop stopped before completing Backports. Debian Installer subsequently displayed its standard success screen despite the failed `07preseed` late command.

**Current fix:** The dispatcher disables *only* active `deb cdrom:` / `deb-src cdrom:` lines in the installed system's classic APT source lists **after the native base installation and before selected custom profiles**. It leaves network repositories unchanged, and refuses unsupported deb822 CD-ROM layouts instead of silently editing mixed-URI stanzas. `apt-setup/disable-cdrom-entries=true` requests Debian's standard later cleanup too. A new ISO-staged `15my-cdd-status` finish-install hook is installed by the early confirmation script, runs after `07preseed` and `14simple-cdd` and before the native `20final-message`, and returns **exit 10 (back up to main menu)** unless the custom status is `COMPLETE` and every user-selected completion marker exists. Ordinary error code 1 from a finish-install script is only warned about; it does not block the native success screen. The new gate does not change the installed Debian files or force a shutdown. **Not yet tested in GTK/text Debian Installer.**


**2026-11-15 VM failure and targeted fix:** The latest ISO successfully installed and booted base Debian after the earlier `zstd` failure. The user's graphical installer log recorded `COMMAND: in-target passwd -S root`, followed by `Unrecognized root account password state`; no optional profile ran and no completion markers were written. Debian Installer 1.155's `in-target` suppresses stdout by default; the common runner now inserts `--pass-stdout` for all captured target commands, including APT simulations and security/SSH checks. Root `chpasswd` uses direct `chroot /target /usr/sbin/chpasswd` with credentials exclusively on stdin rather than `in-target`'s Debconf-reserved stdin. A persistent `/var/log/installer/my-cdd-status` records `INCOMPLETE`, `FAILED`, or `COMPLETE`. **Source-level fix only; installer retesting required.**

**Tasksel limitation:** Debian 13 tasksel 3.81 resets `tasksel/first` to computed GNOME/desktop defaults when `seen=false`, overwriting the requested `ssh-server, standard` values. Conversely `seen=true` can suppress the native editable software-selection screen. The project preserves that native editable screen; select **SSH server** and **standard system utilities**, and deselect **Debian desktop environment** and **GNOME** manually in the next VM test. An automatic default-plus-visible-screen solution remains unresolved without more invasive tasksel integration. Do not report the displayed defaults as fixed or quietly skip the screen.


**Current OMV 8 update behavior (2026-11-15):** The selected OMV profile disables `conf.system.apt.updates.unattendedupgrade`, the `apt` notification schedule, and both periodic APT refreshes and unattended upgrades. It redeploys `apt` and `apticron` via OMV Salt, not the older `cronapt` state. Native installer service-start suppression is checked before optional profiles. No first-boot service masks are written. The revised implementation has not been install-tested.


**Current recovery and service policy:** Before any selected profile executes (including a zero-profile installation), `run-selected.sh` checks the installed root account. If locked/passwordless, it uses Debian Installer's native password-type Debconf questions to set and verify a local root password, with no passwords in source, command arguments or project logs. This GTK/text behavior still requires an actual installer test. Docker is installed with its ordinary service startup defaults; no masking, disabling or OMV-Extras/Compose integration.

**Current review branch (2026-11-15):** No unconditional base user, sudo, SSH or update-policy enforcement. The early confirmation and ordered dispatcher remain; the dispatcher sources only the explicitly selected profile action module. Source-only changes; GTK/text integration has not been retested.

The seven profiles are presented by Simple-CDD's standard `simple-cdd/profiles` Debconf multiselect; none is automatically selected. We must add one custom **summary confirmation** before profile operation, not replace Debian's native installer GUI or its normal keyboard/time/account/network/partman/retry dialogs.

- [`profile-confirm.templates`](profile-confirm.templates) — proposed Debconf note/boolean templates, with **seven independently substituted status lines**, a default-No confirmation and a dependency-error note.
- [`profile-confirm.sh`](profile-confirm.sh) — **wired into [`profiles/default.preseed`](../profiles/default.preseed)** through the approved `preseed/early_command`, before `anna-install simple-cdd-profiles`. It explicitly loads Simple-CDD's generated multiselect and the seven-line confirmation, then sets the original selection's Debconf `seen` flag on approval. A first graphical boot failed at this command (exit code 2); the likely missing-file packaging cause is corrected, but its successful execution is **not yet demonstrated**.
- [`ordered-selection.sh`](ordered-selection.sh) — read-only, deterministic ordering and dependency parser; not a package installer.
- [`run-selected.sh`](run-selected.sh) — existing Debian Installer `preseed/late_command` integration: reads the approved selection, executes only those profiles in the agreed order, displays review and default-No transaction prompts through native Debconf, and logs to the installed target.
- [`profile-common.sh`](profile-common.sh) — shared source helpers for APT suite selection and selected-only update checks. Seven `profile-*.sh` action modules implement Backports, kernel, firmware, ZRAM, tweaks, OMV 8 and Docker; they are loaded only on explicit selection. No upstream udeb patch.
- [`IMPLEMENTATION_GATES.md`](IMPLEMENTATION_GATES.md) — remaining runtime and boot validation requirements.

**Why an early integration is needed:** [Simple-CDD 0.6.9's udeb postinst](https://sources.debian.org/src/simple-cdd/0.6.9/debian/simple-cdd-profiles.postinst) reads `simple-cdd/profiles` then loads preseeds and queues packages in the same script. Its [finish-install hook](https://sources.debian.org/src/simple-cdd/0.6.9/debian/14simple-cdd) later runs executable selected `*.postinst` **inside the target**. Thus an ordinary late profile script cannot replace an early GUI gate, nor guarantee execution order from UI selection alone.

**Asset packaging correction (2026-11-15):** the relative `all_extras` entries were replaced by `profiles/default.extra` because Simple-CDD copies extras after entering its Debian-CD workspace. The build script now compares all assets referenced by the native `profiles/*.extra` manifests against their sources and refuses to report success if they differ. A rebuilt ISO boot test is pending.

**Not yet verified:** execution of the early hook in Debian 13 GTK and text frontends; generated template path, `debconf-loadtemplate` availability, Debconf `seen` semantics avoiding duplicate profile prompts, cancellation/Back navigation, zero-selection behavior and successful transfer to the unmodified udeb. No custom udeb rebuild has been performed. The source now includes the ordered package runner, native review questions, target-root log recording and fail-closed per-profile completion verification. **None has been exercised in real Debian Installer GTK or text mode**. USB boot menu edits, exact repository/daemon compatibility, safe ZRAM partition conversion and first-boot behavior still require validation.

ZRAM backing discovery lives in [`zram-selection.sh`](zram-selection.sh).
It uses an exact unique swap assignment in the installed target's `fstab`
for automatic selection (including reused swap). When that is unavailable,
Debconf's native `Type: select` and `Choices-C` present a safe-default
manual picker in both GTK and text frontends. It checks GPT PARTUUID, type,
signature, mounts, active swap and block holders before destructive actions;
conversion still requires separate default-No confirmation and a targeted
memory-checked swapoff if active. Runtime frontend and partition behavior
remain untested.

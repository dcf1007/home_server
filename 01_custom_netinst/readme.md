# Customized Debian 13 netinst USB

**Project status:** documented installation plan, **not yet a built or tested ISO**. **Updated:** 2026-11-14. **Provenance:** custom server home-server installation decisions and requested GitHub documentation structure.

Prepare an interactive, Simple-CDD-based **Debian 13 (Trixie), amd64** installation USB for a configurable hostname. The example hardware has a **256 GB system SSD** and **32 GB RAM**; these are illustrative, not universal requirements. Confirm actual hardware and the OS installation disk in the installer.

The USB supports UEFI and BIOS booting, highlights **Graphical install**, and waits for Enter; text-based installation and rescue remain available. The intended installed OS is **UEFI/GPT**, minimal/headless, with SSH and Standard system utilities. Disk selection and partition writes are manually confirmed, and both the installer-confirmed administrator account and a separate local root password are entered interactively.

**Installer confirmation:** After profile selection, show an additional **native GTK Debconf summary** of all seven selected/unselected profiles and dependencies, then require **explicit default-No confirmation before selected-profile operations begin**. The text installer uses equivalent Debconf prompts. Debian Installer provides the needed frontend controls, and **the user-approved early-preseed integration (method A) is now wired in source**, before invoking the unmodified Simple-CDD udeb. **It has not been validated in a real GTK or text installer.** If this method fails, stop and obtain further approval before changing methods or removing the summary; never display a misleading late prompt. Disk, partition and package changes still require separate approvals. See [01 preparation](01_custom_cdd_preparation.md) and [08 validation](08_validation_and_pending.md).

**All seven optional profiles start unchecked, in this menu order:** **Backports → Ensure 7.x kernel branch → Extended device support → ZRAM → Debian tweaks → OpenMediaVault 8 → Docker**. The user must explicitly select and confirm every component. **Debian tweaks remains fully functional on Debian's default kernel, independent of Ensure 7.x.** **ZRAM depends on Ensure 7.x**, but remains independent of Debian tweaks. If Ensure 7.x is unchecked when ZRAM is selected, ask to **select Ensure 7.x or deselect ZRAM**. **If Backports is already selected, Ensure 7.x prefers eligible Backports 7.x image/headers first; otherwise it checks normal Debian repositories first**, asking to explicitly select Backports only if normal repositories lack Linux 7.x. Backports is maintained at Debian's default priority **100**; its profile alone owns the reviewed full upgrade and cleanup, while Ensure 7.x installs **only kernel-related packages** selectively from Backports when needed. No other profile is silently selected.

## Key constraints

- **Installer GUI settings:** suggested hostname, administrator username, local domain, installer language/locale, Spanish keyboard, `Europe/Berlin` timezone, UTC RTC, DHCP and tasksel selections are centralized in [profile_defaults.conf](my-cdd/profile_defaults.conf), editable and confirmed in the native installer regardless of optional profiles. No passwords or disk target are stored.
- **Manual OS disk selection:** verify the target device and explicitly confirm destructive partitioning operations before proceeding.
- Root filesystem: **ext4** without LVM, encryption or separate `/boot`; normal ext4 defaults remain unchanged. The optional Debian tweaks profile adds non-default `noatime,errors=panic` mount options and prevents automatic filesystem repairs.
- Installer EFI partition **1 GiB**; the user may create a swap partition in manual partitioning (**16 GB suggested**). **Without ZRAM**, use it as ordinary swap; **with ZRAM**, as the first ZRAM profile operation detect and confirm the exact partition, then **immediately** convert it (before other ZRAM provisioning) to **raw unformatted** GPT type **8300** (`Linux filesystem`), name it **`zram-writeback`** as **GPT PARTLABEL**, and use its **PARTUUID** for ZRAM backing. If already activated as swap, require memory safety review and **separate consent for targeted `swapoff`**, with verified success before conversion; otherwise stop. Never leave the physical backing active as conventional swap. If none was created and ZRAM is selected, offer to return to partitioning or deselect ZRAM. No swap and no ZRAM is permitted after Debian Installer's normal warning.
- The separately selected **Ensure 7.x kernel branch** profile installs the **newest eligible Linux 7.x image and matching headers**, without a fixed version lock. **When Backports is selected**, it prefers a compatible **Backports 7.x** kernel and headers first, otherwise reviews normal 7.x candidates. **Without Backports selected**, it checks normal repositories and explicitly requests Backports only if needed. **Backports** performs an explicitly approved normal full upgrade of all eligible installed packages under priority **100**, followed by separately reviewed **autoremove/purge cleanup**. Removals require review/approval; preserve the stable fallback kernel initially. Installed GRUB menu remains visible for **5 seconds**, defaulting to the newest kernel.
- When **Extended device support** is selected, attempt to install **both** `intel-microcode` **and** `amd64-microcode` regardless of detected CPU vendor, together with **broad proactive firmware** (networking, storage, wireless, graphics, audio and others). **When Backports was explicitly selected**, first prefer eligible Backports versions for every firmware and microcode package via targeted suite selection; if none is suitable, review normal Debian versions before considering omission. **List every Stable fallback by package, version, origin and reason in the final APT transaction; one explicit approval of that transaction covers all those fallbacks, without separate per-package fallback prompts.** **Without Backports**, use normal repositories. Simulate the combined transaction. Any **unavailable or conflicting microcode or firmware package** is shown individually with its actual reason and omitted **only after explicit approval**; warn about security/stability consequences if the applicable CPU microcode is omitted. Re-simulate and install all remaining compatible packages, logging each omission and approval. **Omissions still require individual approval; Stable version fallbacks do not.** Never silently reduce coverage. The inventory is in [10 Extended device support](10_extended_device_support.md); simultaneous microcode installation remains **untested**. Debian Installer's standard firmware detection remains available with this option unchecked.
- the installer-confirmed administrator account: sudo and initial SSH password login. Separate local root password before first reboot; root SSH login prohibited.
- **Manual software updates and reboots only**. Explicitly disable Debian unattended upgrades in Debian tweaks, and disable OMV's scheduled cron-apt when OMV is selected.
- Docker packages install if selected, **without activating Docker daemon/socket** during installation or on first boot.
- The ZRAM profile alone sets `vm.swappiness=100` using `/etc/sysctl.d/90-zram-swappiness.conf`; no ZRAM-specific swappiness change when the profile is unchecked.
- **Standard Debian Installer interactions stay native:** use the normal GUI/text questions for networking, mirror selection, standard retrieval and retry, and APT mirror configuration after installation. **Do not add duplicate custom dialogs or ask a separate mirror-persistence question (Decision 118 withdrawn).** Custom optional-profile failures reuse existing recovery when feasible; otherwise stop with diagnostics. Never silently change repositories, enable Backports, skip selected profiles, bypass signatures or claim success.
- If a selected profile fails critical checks **or the network/repository error is not resolved**, **stop and always display diagnostics, a sensitive-log warning, and an option to manually export complete logs**. Save **full, unredacted** custom installer logs in **`/target/var/log/installer/`** when the correct target filesystem is safely mounted/writable; **also save an unredacted copy to a safely writable area of the installer USB if possible**, reporting each outcome. Use restrictive permissions **where supported**, never assume removable media enforces them, and warn that logs may contain credentials or other private data. Do not deliberately log new secrets. Never repartition, format or overwrite USB boot content to enable logging. Recovery or reinstallation is **manual**; no silent alternative or false success, installer-managed snapshots, backup images or automatic rollback.
- **No separate installer-media verification:** no checksum/signature verification of the Debian source image, no generated-ISO hash, no USB read-back/comparison and no verification-only media boot test. This does not disable signed APT package metadata checks or change the required USB boot capabilities.
- ZRAM initialization failure must enter emergency mode; ZRAM monitor failure must be logged and retried without emergency mode.
- **Backports uses the default priority 100, not 900.** No blanket preference for backported packages. **When explicitly selected**, eligible kernel 7.x packages and Extended device support's firmware/microcode packages are **selected from Backports first through targeted per-package requests**, with Stable fallback and transaction review. Other packages keep Debian's normal priority policy; validate all dependencies, particularly with OMV.

## Scope and provenance

These pages distinguish **approved user choices** from **engineering proposals requiring validation**. **Do not reinvent or separately decide ordinary Debian Installer prompts; confine additional questions and custom installer UI to genuinely nonstandard selected-profile requirements.** The [`my-cdd/`](my-cdd/README.md) directory contains **initial Simple-CDD build configuration, seven selectable profile source stubs, the approved early Debconf confirmation hook, firmware source inventory and original ZRAM code assets**. Extra offline test harnesses and unused inspection helpers were removed on request. The installed-target profile implementations and functional validation remain incomplete, and **no custom ISO or USB has been built**. The minimal build script stops while profiles still contain unfinished hooks.

**Primary sources:** user's extended Debian 13 installation planning conversation and uploaded `zram_zstd_writeback_design(1).md`; official Debian, APT, Simple-CDD, Linux, Docker and OpenMediaVault documentation linked in the numbered pages.
